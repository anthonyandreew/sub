# ProxyPlankton · Mihomo / Clash Mi

Готовая конфигурация для Clash Mi: включить VPN одной кнопкой, дальше телефон
сам проверяет доступные подключения и выбирает узел. Профили и состав серверов
автоматически обновляются из исходной подписки.

## Подключение на iPhone

В Clash Mi добавьте **удалённый профиль по URL**:

```text
https://raw.githubusercontent.com/anthonyandreew/sub/main/VPN_Mihomo_Auto.yaml
```

Включите автоматическое обновление удалённого профиля в приложении, например
раз в час. Импорт отдельного скачанного файла не обеспечивает обновление всей
конфигурации. Включайте режим **Rule / Правила**, затем VPN. Выбирать сервер не нужно:
в группе `Proxy` по умолчанию выбран `Auto Pre`. При необходимости в `Proxy`
можно вручную выбрать обычный сервер из общего списка. Для автоматического
резервирования оставьте `Proxy → Auto Pre`.

## Как обновляется список

1. GitHub Actions читает источники из `MIHOMO_SUBSCRIPTION_URL` и необязательного
   `MIHOMO_WHITELIST_SOURCE`. Каждый секрет принимает одну или несколько строк:
   HTTPS-ссылки на подписки, отдельные VLESS или Hysteria2 URI.
   Запуск по расписанию каждые 30 минут (`:17` и `:47`); возможны задержки GitHub.
2. Генератор выбирает только VLESS и Hysteria2 (`hy2://` тоже подходит),
   разделяет обычные узлы и резерв обхода белых списков, добавляет новые узлы, меняет параметры существующих
   и убирает удалённые. Точные дубликаты соединений удаляются; разные узлы с
   одинаковым именем получают разные имена.
   Остальные типы пропускаются, их количество по типам выводится в журнал.
   Доступность с компьютера/CI не влияет на выбор: мобильная сеть может
   пропускать другие подключения.
3. После тестов и проверки настоящим ядром Mihomo публикуются провайдер
   `mihomo/providers/proxyplankton_sub_clash.yaml`, отдельный резерв
   `mihomo/providers/proxyplankton_whitelist.yaml` и полный профиль `VPN_Mihomo_Auto.yaml`.
4. Работающее ядро на телефоне запрашивает обновление провайдера раз в час.
   Это обновляет узлы без повторного импорта всего профиля.
5. Полное обновление профиля средствами Clash Mi обновляет также правила и
   встроенный запасной список для первого запуска.

Обновление узлов обычно доходит за следующий запуск Actions плюс до часа
работающего ядра. Это не гарантия точного срока: расписание GitHub и фоновые
ограничения iOS могут задержать обновление.

При первом запуске без доступа к GitHub используется встроенный список узлов.
Далее ядро сохраняет скачанный провайдер в своём кэше. После успешного обновления
удалённые узлы не остаются отдельными статическими кандидатами `Auto Pre`.
Ошибочный/пустой ответ любого источника, повреждённая запись VLESS/Hysteria2,
отсутствие узлов разрешённых типов или ошибка проверки останавливают публикацию,
сохраняя последние рабочие файлы. Если изменений нет, новый коммит не создаётся.

## Автовыбор и маршрутизация

Если задан `MIHOMO_WHITELIST_SOURCE`, группа `Auto Pre` работает по приоритету:

1. `Auto Final` выбирает лучший доступный обычный узел по задержке.
2. `Auto Pre` проверяет обычные узлы по отдельности, чтобы задержка переключения
   внутри `Auto Final` не включила платный резерв.
3. Затем, только если обычные узлы недоступны, используется резерв обхода БС.
4. После восстановления обычных узлов новые соединения возвращаются на обычный пул.

Пинг CDN не даёт ему приоритета, даже если он быстрее всех. Резерв проверяется
на доступность; его можно проверить вручную в приложении. Узлы резерва исключены
из обычного провайдера, включая дубликаты с другим названием. Название CDN берётся
из части ссылки после `#` и не определяет его роль: роль задаётся секретом.
Без резервного источника `Auto Pre` остаётся обычной группой `url-test`.

| Параметр | Значение | Назначение |
| --- | --- | --- |
| Группы | `Auto Pre`: `fallback`; `Auto Final`: `url-test` | Приоритет обычного пула, внутри пула — выбор по задержке |
| Проверка | `https://www.gstatic.com/generate_204` | Проверяет путь через каждый узел |
| Интервал | 60 секунд | Периодические проверки при использовании провайдера |
| Таймаут | 5 секунд | Максимальное ожидание одной проверки |
| Lazy | `true` | Пропускает периодические проверки, если провайдер не использовался за последний интервал |
| Tolerance | 50 мс | Уменьшает переключения из-за небольших колебаний |
| Неудачные подключения | `max-failed-times: 2` | Повод для внеочередной проверки группы |
| Пустая группа | `REJECT` | Не отправляет весь зарубежный трафик напрямую |

Успешная проверка означает доступность тестового URL, а не гарантию работы
каждого сайта. При смене узла существующее соединение может оборваться;
новые соединения используют выбранный узел.

Периодические проверки узлов из `use` задаются в `proxy-providers` →
`health-check`. Настройки Auto Pre согласованы с ними. Ошибки подключения могут
вызвать внеплановую проверку; таймаут 5 секунд не гарантирует переключение
за 5 секунд. При простое с `lazy: true` данные о доступности могут устаревать
до следующей проверки. Обновление списка провайдера раз в час независимо
от проверки доступности раз в минуту.

Локальные сети и российские назначения из правил идут `DIRECT`, остальное —
через `Proxy` (по умолчанию Auto Pre). DNS российских доменов использует Яндекс; остальной DNS —
Cloudflare DoH через `Auto Pre`. Для запуска проверок и загрузки провайдера
используется системное разрешение имён соответствующих служебных доменов.
Провайдер загружается через `Proxy`: встроенный список позволяет сначала
запустить доступный узел, затем запросить GitHub через него. Это проверено
тестом настоящего ядра с недоступным напрямую адресом источника.

Правила встроены в полный профиль. Их исходники остаются в `stash/rules/`:
это общий набор данных, название каталога не означает зависимость от Stash.

## Настройка GitHub Actions

В **Settings → Secrets and variables → Actions** задайте repository secret:

```text
MIHOMO_SUBSCRIPTION_URL = ссылка на основную подписку
MIHOMO_WHITELIST_SOURCE = необязательный резерв для обхода белых списков
```

В каждом секрете одна запись на строку, без JSON и кавычек. Например:

```text
https://provider.example/subscription/PRIVATE_TOKEN
https://another-provider.example/subscription/PRIVATE_TOKEN
vless://UUID@cdn.example.com:443?...&extra=URL_ENCODED_JSON#CDN
```

Обычные источники добавляйте в `MIHOMO_SUBSCRIPTION_URL`, платный резерв —
только в `MIHOMO_WHITELIST_SOURCE`. Старое имя `MIHOMO_ADDITIONAL_SOURCES`
больше не используется. Для обновления
CDN предпочтительна ссылка на WPP-подписку: после изменения подключения в WPP
сборка сама получит новые параметры. Отдельная VLESS-ссылка тоже подходит,
но при изменении сервера её потребуется заменить в секрете. Источники из
двух секретов хранятся в отдельных провайдерах; основной секрет можно не менять.

Старый секрет `STASH_SUBSCRIPTION_URL` поддерживается как запасной источник,
если новый ещё не задан. Не удаляйте его до настройки нового.
Затем **Actions → Update Mihomo profiles → Run workflow → main**.
Редактирование секрета само по себе не запускает Actions: нужен ручной запуск
или следующий запуск по расписанию. При первом переходе с прежнего профиля
один раз обновите полный профиль в Clash Mi, чтобы появились новая структура `Auto Pre` и группа `Auto Final`,
и выберите `Proxy → Auto Pre`.
Дальнейшие изменения серверов, UUID и XHTTP-параметров приходят с обновлением
провайдера и не требуют повторного импорта профиля.
Для записи сгенерированных файлов workflow использует `GITHUB_TOKEN`
с разрешением `contents: write`.

Исходный URL не включается в сгенерированные файлы. Но **сами YAML содержат
UUID/пароли узлов**: в публичном репозитории они доступны всем читателям.
Секрет Actions скрывает URL источника, но не делает опубликованные узлы приватными.
Публикация семейных подключений требует решения владельца об этом доступе.

## CDN VLESS/XHTTP и обход белых списков

Сборщик понимает URL-encoded JSON в параметре `extra` VLESS-ссылки и переводит
его из Xray в формат Mihomo. Сохраняются GET, размещение данных в заголовке
X-Data, размеры пакетов, интервалы и XMUX из проверенного подключения:

| Поле ссылки Xray | Поле Mihomo xhttp-opts |
| --- | --- |
| uplinkHTTPMethod | uplink-http-method |
| uplinkDataPlacement / uplinkDataKey | uplink-data-placement / uplink-data-key |
| uplinkChunkSize | uplink-chunk-size |
| scMaxEachPostBytes / scMinPostsIntervalMs | sc-max-each-post-bytes / sc-min-posts-interval-ms |
| xmux.maxConcurrency / xmux.maxConnections | reuse-settings.max-concurrency / max-connections |

Числовые значения/диапазоны приводятся к строкам, как в проверенном профиле
Mihomo 1.19.32. `serverMaxHeaderBytes` относится к серверу и в клиент не переносится.
Неизвестные поля extra/XMUX, конфликтующие настройки и некорректный JSON
останавливают сборку, а не удаляются молча. Обычный XHTTP без extra поддерживается.

CDN из `MIHOMO_WHITELIST_SOURCE` участвует только в резервном провайдере после всех обычных узлов.
Проверка в CI проверяет конфигурацию и механику обновлений; реальную доступность
при белых списках проверяют на мобильной сети. Если все сохранённые узлы уже
недоступны, получение новых параметров потребует сети с доступом к GitHub.

## Локальная проверка

Нужен Python 3.10+ без сторонних библиотек:

```sh
python3 -m unittest discover -s tests -v
python3 scripts/build_mihomo.py --input /path/to/subscription.txt --output-dir .private/preview
```

Или передайте URL через переменную окружения `MIHOMO_SUBSCRIPTION_URL`.
Для проверки ядром используйте `mihomo -t -d /tmp/mihomo-check -f
.private/preview/VPN_Mihomo_Auto.yaml` (одной строкой).
CI использует закреплённый Mihomo v1.19.32 и сверяет SHA-256 архива.

В Auto Pre попадают только URI VLESS и Hysteria2 (`hysteria2://` и `hy2://`).
WireGuard, AmneziaWG (`@_wg://` и `amneziawg://`), Mieru, `vpn://` и другие
типы намеренно исключаются, даже если ядро умеет соответствующий протокол.
В журнале указываются только типы и количество исключённых записей, без ключей
и URL. Служебные метаданные Happ/Incy пропускаются без предупреждений.
Ошибки в записях разрешённых типов не скрываются и останавливают публикацию.
Для TLS gRPC ALPN нормализуется в `h2`, необходимый этому транспорту.

`scripts/build_stash_provider.py` используется действующей сборкой Mihomo как
библиотека разбора URI. Папка `stash/rules/` содержит её рабочие правила;
эти имена не означают зависимость от клиента Stash. Старые профили Stash и
дублирующий профиль Clash Mi удалены; генератор публикует только основной
профиль Mihomo и два провайдера.

## Отдельная подписка Karing

Тестовый JSON с актуальным CDN/XHTTP и прежними правилами маршрутизации:

```text
https://raw.githubusercontent.com/anthonyandreew/sub/refs/heads/main/karing_finland_wl_config.json
```

Файл обновлён под новый CDN; прежнее имя `finland` в URL оставлено для
совместимости ссылки. Название узла берётся из текущего резервного провайдера.

Для сравнения подготовлена отдельная копия Clash-профиля:

```text
https://raw.githubusercontent.com/anthonyandreew/sub/refs/heads/main/VPN_Karing_Auto_Test.yaml
```

В ней все подключения находятся в верхнеуровневом `proxies`, а `use` заменены
явными списками. Это устраняет зависимость импорта от поддержки встроенного
`proxy-providers.payload`; параметры XHTTP сохранены полностью. Основной профиль
Mihomo при этом не изменяется. В копии записан приоритет обычных узлов перед CDN,
однако Karing может перестроить группы и правила при импорте. Не следует считать
проверенным резервирование только потому, что файл успешно импортировался.
Для первой проверки CDN выбрать его вручную в отдельной тестовой подписке.

Сначала проверить JSON в Karing Android 1.2.25.2802. Включить сохранение правил
провайдера и группу этой подписки в маршрутизации. Если CDN не импортируется или
не проходит проверку подключения, сохранить точный текст ошибки и посмотреть
конфигурацию импортированного узла: наличие узла ещё не подтверждает сохранение
session/seq/padding/XMUX. Нельзя удалять эти поля ради успешного импорта:
сервер использует их для размещения данных и идентификаторов сеанса.

Оба файла — экспериментальные снимки, без автоматического обновления из Actions.
Подготовка из последнего опубликованного Mihomo-профиля:
`python3 scripts/build_karing_test.py`. Сборщик сохраняет правила старого JSON
и останавливается на неизвестных параметрах XHTTP, вместо потери настроек.
Поддержка дополнительных полей `transport` именно Karing требует проверки на
Android; схема расширенного sing-box не является гарантией совместимости Karing.
